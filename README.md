# WorkSync

面向固定小团队的任务协作工具：分配任务、跟进进度、按月回顾工作，并集中保存团队公用的文字信息。

当前交付以**本地开发和调试**为主。React 页面与 Fastify API 使用真实 SQLite 数据；生产构建可以由一个 Node.js 进程提供服务，服务器打包和 Docker 留到后续。

## 本地启动

需要 Node.js **22.22 或更新版本**及 npm。

```bash
npm ci
npm run seed:dev
npm run dev
```

打开 **http://localhost:5173**。前端运行于 5173，API 运行于 3000，由前端开发服务代理 `/api` 请求。前后端均支持修改代码后自动更新。

`seed:dev` 只允许初始化空的开发数据库，不会覆盖已有账号或任务。已有数据时，直接执行 `npm run dev`。

### 使用自己的账号

如需一个没有演示数据的本地空间，在停止服务后指定新的数据目录，并初始化首位管理员：

```bash
DATA_DIR=./data/my-team npm run admin:create
DATA_DIR=./data/my-team npm run dev
```

命令会询问用户名、姓名和密码，密码输入不会明文回显。也可通过 `ADMIN_USERNAME`、`ADMIN_NAME`、`ADMIN_PASSWORD` 环境变量进行非交互初始化。已有成员时，通过管理员页面添加账号或重置密码。

管理员创建的账号及被重置密码的账号，首次登录后必须修改密码。修改密码会注销该成员的旧会话。

## 使用方式

- **任务管理**：成员可自由创建任务并分配给有效成员。标题和负责人必填，说明和截止日期可选；支持列表、看板、搜索、日期/状态筛选，以及归档与恢复。
- **可见范围**：普通成员只能查看自己负责或创建的任务，双方均可维护内容、改期、转交、更新状态。管理员可查看和管理全部任务。
- **站内通知**：接收别人分配的任务时通知；未完成任务在截止前一天及逾期后各提醒一次。关闭网页后不会向外部渠道发送消息。
- **月度总结**：成员可看自己的记录，管理员可看任意成员及团队汇总。可一键复制为文本；浏览器限制自动复制时，会提供已选中的文本供手动复制。
- **团队共享**：全员可查看和发布文字及链接；作者和管理员可编辑、删除。管理员维护分类和置顶。删除分类只将条目移至“未分类”，不会删除正文。
- **成员停用**：有未完成且未归档任务时，必须选择接收人统一转交；完成记录和共享内容仍保留，旧会话立即失效。至少保留一位有效管理员。

首版不包含项目分组、优先级、子任务、任务评论、附件、自动重复任务或外部通知。

### 月报的统计口径

业务日期采用 **Asia/Shanghai**，时间戳以 UTC 保存。任务截止日期包含当天，次日才视为逾期。

- 当前月统计截至查询时刻；历史月统计截至次月 1 日上海时间 00:00，排除该时点及之后的变更。
- 事项按统计时点的负责人归属。例如 A 完成任务后，在当月月底前转交给 B，计入 B 的当月总结；下个月才转交，上月总结不变。
- 统计时仍为“已完成”，且最近一次完成时间在该月的任务计入完成清单。同一任务反复完成不会重复计数。
- 未完成、未归档的任务继续列入，包括以前月份创建的任务。完成后归档仍保留在对应月份的完成清单中。
- 修改标题、负责人、状态、日期以及归档操作都会生成不可变快照；报表使用当时的快照，不使用任务的最新内容替代过去的记录。
- 系统自动记录实际操作时间，不提供历史补录或修改完成时间的接口。


### 在本地检查生产构建

先停止占用 3000 端口的开发后端，然后执行：

```bash
npm run build
DATA_DIR=./data/dev npm start
```

打开 **http://localhost:3000**，此时页面和 API 均由一个进程提供，使用已有开发数据。

不指定 `DATA_DIR` 时，源码开发默认使用 `data/dev/worksync.sqlite`，编译后的服务默认使用 `data/production/worksync.sqlite`。新的生产数据库需先运行：

```bash
node dist/server/cli.js admin
npm start
```

## 配置与数据保留

可以复制 `.env.example` 为 `.env`。配置文件、数据库、备份、日志及测试输出均已加入忽略规则。

| 配置项 | 默认值 / 说明 |
| --- | --- |
| `HOST` | `127.0.0.1`，本地监听 |
| `PORT` | `3000`，Vite 的 API 代理也读取此配置 |
| `DATA_DIR` | 开发为 `data/dev`，生产构建为 `data/production` |
| `BACKUP_DIR` | 数据目录下的 `backups/` |
| `APP_ORIGIN` | 可显式配置实际网页入口，用于请求来源校验 |
| `COOKIE_SECURE` | `false`；使用 HTTPS 后设为 `true` |
| `JOBS_DISABLED` | 测试时可设为 `true`，默认启用提醒和自动备份 |

服务使用同源接口、密码哈希、服务端会话和 HttpOnly Cookie；会话有效期为 7 天。创建、编辑、列表、搜索、统计、通知和导出所用接口均执行权限校验。

### 备份与恢复

服务每分钟检查提醒，在上海时间每天 03:00 后执行一次自动备份；停机错过时间后会在启动时补备。SQLite 备份接口保证运行中的数据库也能得到一致性副本，最近 7 份自动或手动备份会保留。

```bash
# 服务运行时也可以手动备份
npm run backup

# 停止服务后再恢复，路径以实际备份文件为准
npm run restore -- ./data/dev/backups/worksync-实际时间戳.sqlite
```

为其他数据目录操作时，命令需使用同一个 `DATA_DIR`。生产构建也可以使用 `node dist/server/cli.js backup` 和 `node dist/server/cli.js restore <路径>`。

恢复前会验证备份完整性和数据库版本，并额外保存当前数据库的 `pre-restore-*.sqlite` 副本。此类恢复前副本不会被每日 7 份保留规则清理。恢复后的旧登录会话会被清除，成员需要重新登录。

备份保存在本机，若需要防范磁盘故障，应将备份目录另行复制到其他设备。不要只复制运行中的主 `.sqlite` 文件，SQLite 的 WAL 文件也可能包含尚未合并的写入；请使用上述备份命令。

## 代码结构

```text
client/         页面、交互、账号状态及样式
server/         API、权限、SQLite、调度与维护命令
shared/         前后端共享类型、上海日期处理和月报文本格式
tests/          后端测试与独立浏览器验收环境
public/         站点图标
```

数据库用 `user_version` 管理版本。任务每次更新在一个事务中写入当前状态及完整快照，停用成员的任务转交也在事务中完成。任务、共享条目使用版本号处理并发更新，冲突时返回 `409`，界面保留输入直到主动重新加载。

后续服务器交付将使用构建产物、锁定的依赖清单和独立配置；不携带开发数据库或本地 `node_modules`。SQLite 驱动含平台相关组件，需要根据服务器操作系统和 CPU 安装生产依赖。
