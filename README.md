# WorkSync

面向固定小团队的任务协作工具：分配任务、跟进进度、按月回顾工作，并集中保存团队公用的文字信息。

React 页面与 Fastify API 使用真实 SQLite 数据；生产构建由一个 Node.js 进程同时提供页面和接口，可打包后部署到服务器（见[服务器部署](#服务器部署)）。Docker 镜像留到后续。

## 本地启动

需要 Node.js **22.22 或更新版本**及 npm。

```bash
npm ci
npm run seed:dev
npm run dev
```

打开 **http://localhost:5173**。前端运行于 5173，API 运行于 3000，由前端开发服务代理 `/api` 请求。前后端均支持修改代码后自动更新。

`seed:dev` 只允许初始化空的开发数据库，不会覆盖已有账号或任务。已有数据时，直接执行 `npm run dev`。

### 使用自己的账号

如需一个没有演示数据的本地空间，在停止服务后指定新的数据目录，并初始化首位管理员：

```bash
DATA_DIR=./data/my-team npm run admin:create
DATA_DIR=./data/my-team npm run dev
```

命令会询问用户名、姓名和密码，密码输入不会明文回显。也可通过 `ADMIN_USERNAME`、`ADMIN_NAME`、`ADMIN_PASSWORD` 环境变量进行非交互初始化。已有成员时，通过管理员页面添加账号或重置密码。

管理员创建的账号及被重置密码的账号，首次登录后必须修改密码。修改密码会注销该成员的旧会话。

## 使用方式

- **探索入口**：点击右上角工具栏的“搜索或跳转”，或使用 `Ctrl+K` / `⌘K` 搜索功能。可以直接新建任务、打开月报或发布共享信息；管理员还可以快速进入团队管理。
- **外观主题**：登录页和工作区右上角工具栏均可选择浅色、深色或跟随系统，默认跟随系统。设置保存在当前浏览器，在其他标签页同步生效；存储不可用时仍可临时切换。
- **任务管理**：成员可自由创建任务并分配给有效成员。标题和至少一位负责人必填，可同时指定多位负责人，大家共享同一份进度；说明和截止日期可选。支持列表、看板、搜索、日期/状态筛选，以及归档与恢复。任务页顶部的概览显示进行中数量与状态分布、今天截止、已逾期和完成进度，点击“今天截止”“需要跟进”可直接筛选。点击日期入口直接展开范围日历，选择起止日期即生效，同一天点两次可筛选单日；也可一键选择今天、本周（周一至周日）、本月，或未来 7 天、已逾期、无截止日期。范围包含首尾两天，列表、看板和概览使用同一筛选；日期按上海时区计算。看板任务可通过拖动手柄放到工具栏归档图标，松手立即归档；点击归档图标可查看并恢复任务。键盘拖动时，左右键切换状态列，上键移至归档，下键返回任务列，空格放下，Escape 取消。
- **可见范围与权限**：普通成员只能查看自己负责或创建的任务。创建者和管理员可以修改内容、改期、调整负责人、归档和恢复；负责人可以更新状态（包括标记完成和在看板中拖动换列），其余内容只读。管理员可查看和管理全部任务。
- **站内通知**：接收别人分配的任务时通知；未完成任务在截止前一天及逾期后各提醒一次。有人发布团队共享信息时，其他有效成员收到未读通知；活跃页面每 10 秒检查一次，回到页面时立即刷新，新共享通知会弹出一次提示，多条合并显示。点击提示或铃铛中的通知可打开完整内容并标为已读，仅关闭提示不会标为已读。首次打开时，历史未读保留在铃铛中；关闭网页后不会向外部渠道发送消息。
- **月度总结**：成员可看自己的记录，管理员可看任意成员及团队汇总。可一键复制为文本；浏览器限制自动复制时，会提供已选中的文本供手动复制。
- **团队共享**：全员可查看和发布文字及链接；作者和管理员可编辑、删除。管理员维护分类和置顶。删除分类只将条目移至“未分类”，不会删除正文。发布内容与生成通知在同一事务中完成；编辑、置顶不再次群发，删除信息会清理关联通知。通知详情通过独立链接打开，不受共享列表的搜索、分类和分页限制。
- **成员停用**：有未完成且未归档任务时，必须选择接收人统一转交；完成记录和共享内容仍保留，旧会话立即失效。至少保留一位有效管理员。

首版不包含项目分组、优先级、子任务、任务评论、附件、自动重复任务或外部通知。

### 界面设计

工作区采用“悬浮玻璃岛”布局：左侧导航是一块离开屏幕边缘的圆角面板，右上角的工具栏集中放置搜索、主题、通知和账号菜单；手机上导航收进抽屉。整体以冷调中性色为底，只保留一种青绿强调色。卡片悬停时轻微浮起，看板拖动时任务卡片会抬起、倾斜并加深阴影，任务详情以悬浮抽屉打开。

登录页沿用同一套设计语言：左侧是一叠示意任务卡片，鼠标移动时有轻微视差；右侧是登录卡片。没有持续运行的动画或画布绘制。

界面适配明暗主题与手机屏幕，并遵守系统的无障碍设置：开启“减少动态效果”时停用入场动画和视差；开启“减少透明度”或浏览器不支持背景模糊时，玻璃面板改为实色；强制颜色模式下保留边框和选中状态。

旧的 `/login-preview` 预览地址已移除：未登录时显示正式登录页，已登录时跳转到任务页。

### 月报的统计口径

业务日期采用 **Asia/Shanghai**，时间戳以 UTC 保存。任务截止日期包含当天，次日才视为逾期。

- 当前月统计截至查询时刻；历史月统计截至次月 1 日上海时间 00:00，排除该时点及之后的变更。
- 事项按统计时点的负责人归属。例如 A 完成任务后，在当月月底前转交给 B，计入 B 的当月总结；下个月才转交，上月总结不变。
- 统计时仍为“已完成”，且最近一次完成时间在该月的任务计入完成清单。同一任务反复完成不会重复计数。
- 未完成、未归档的任务继续列入，包括以前月份创建的任务。完成后归档仍保留在对应月份的完成清单中。
- 修改标题、负责人、状态、日期以及归档操作都会生成不可变快照；报表使用当时的快照，不使用任务的最新内容替代过去的记录。
- 系统自动记录实际操作时间，不提供历史补录或修改完成时间的接口。

## 服务器部署

### 打包

```bash
npm run package
```

脚本会清空并重新构建 `dist/`（含类型检查），生成 `release/worksync-版本号-提交号.tar.gz`；工作区有未提交改动时，提交号后带 `-dirty`。包内只有构建产物、`package.json`、`package-lock.json`、`.env.example`、本说明和 `deploy/worksync.service`，不含 `node_modules`、`.env` 和任何数据库。

### 安装

服务器需要 Node.js **22.22 或更新版本**。依赖在服务器上用 `npm ci --omit=dev` 安装，版本由 `package-lock.json` 锁定。SQLite 驱动 `better-sqlite3` 自带 Linux（x64、arm64，含 Alpine）、macOS 和 Windows 的预编译文件，安装时无需下载或编译。

```bash
# 以 /opt/worksync 为例
sudo useradd --system --home /opt/worksync --shell /usr/sbin/nologin worksync
sudo mkdir -p /opt/worksync
sudo tar -xzf worksync-*.tar.gz -C /opt/worksync --strip-components=1
sudo chown -R worksync:worksync /opt/worksync
cd /opt/worksync
sudo -u worksync npm ci --omit=dev
sudo -u worksync cp .env.example .env    # 按下文修改
sudo -u worksync node dist/server/cli.js admin
```

`.env` 中需要关注的配置：

- **直接用 IP 和端口访问**：设 `HOST=0.0.0.0`，`APP_ORIGIN=http://服务器地址:3000`，并在防火墙放行该端口。
- **经 Nginx 等反向代理访问**：保持 `HOST=127.0.0.1`，`APP_ORIGIN` 设为浏览器中的实际地址。代理需要转发原始 `Host` 请求头。启用 HTTPS 后设 `COOKIE_SECURE=true`。

服务从当前目录读取 `.env` 和 `dist/public`，数据默认写入 `data/production/`，因此要在解压目录中启动。

### 用 systemd 常驻运行

```bash
sudo cp deploy/worksync.service /etc/systemd/system/   # 先按实际修改用户、目录和 node 路径
sudo systemctl daemon-reload
sudo systemctl enable --now worksync
journalctl -u worksync -f                              # 查看日志
```

### 升级

```bash
sudo -u worksync node dist/server/cli.js backup        # 先备份
sudo systemctl stop worksync
sudo tar -xzf worksync-新版本.tar.gz -C /opt/worksync --strip-components=1
sudo chown -R worksync:worksync /opt/worksync
cd /opt/worksync && sudo -u worksync npm ci --omit=dev
sudo systemctl start worksync
```

解压只覆盖程序文件，`.env` 和 `data/` 保持不变；新版本启动时自动升级数据库。旧版本已删除的文件会留在 `dist/` 中，但不会被加载。

## 配置与数据保留

可以复制 `.env.example` 为 `.env`。配置文件、数据库、备份、日志及测试输出均已加入忽略规则。

| 配置项 | 默认值 / 说明 |
| --- | --- |
| `HOST` | `127.0.0.1`，本地监听 |
| `PORT` | `3000`，Vite 的 API 代理也读取此配置 |
| `DATA_DIR` | 开发为 `data/dev`，生产构建为 `data/production` |
| `BACKUP_DIR` | 数据目录下的 `backups/` |
| `APP_ORIGIN` | 可显式配置实际网页入口，用于请求来源校验 |
| `COOKIE_SECURE` | `false`；使用 HTTPS 后设为 `true` |
| `JOBS_DISABLED` | 测试时可设为 `true`，默认启用提醒和自动备份 |

服务使用同源接口、密码哈希、服务端会话和 HttpOnly Cookie；会话有效期为 7 天。创建、编辑、列表、搜索、统计、通知和导出所用接口均执行权限校验。

### 备份与恢复

服务每分钟检查提醒，在上海时间每天 03:00 后执行一次自动备份；停机错过时间后会在启动时补备。SQLite 备份接口保证运行中的数据库也能得到一致性副本，最近 7 份自动或手动备份会保留。

```bash
# 服务运行时也可以手动备份
npm run backup

# 停止服务后再恢复，路径以实际备份文件为准
npm run restore -- ./data/dev/backups/worksync-实际时间戳.sqlite
```

为其他数据目录操作时，命令需使用同一个 `DATA_DIR`。生产构建也可以使用 `node dist/server/cli.js backup` 和 `node dist/server/cli.js restore <路径>`。

恢复前会验证备份完整性和数据库版本，并额外保存当前数据库的 `pre-restore-*.sqlite` 副本。此类恢复前副本不会被每日 7 份保留规则清理。恢复后的旧登录会话会被清除，成员需要重新登录。

备份保存在本机，若需要防范磁盘故障，应将备份目录另行复制到其他设备。不要只复制运行中的主 `.sqlite` 文件，SQLite 的 WAL 文件也可能包含尚未合并的写入；请使用上述备份命令。

## 代码结构

```text
client/         页面、交互与账号状态
client/styles/  样式：tokens.css 定义颜色、圆角、字号、阴影和动效等设计变量，其余按基础、控件、外壳、弹层和页面拆分，由 index.css 统一引入
server/         API、权限、SQLite、调度与维护命令
shared/         前后端共享类型、上海日期处理和月报文本格式
tests/          后端测试与独立浏览器验收环境
public/         站点图标与主题初始化脚本
scripts/        服务器部署包的打包脚本
deploy/         systemd 服务示例
```

数据库用 `user_version` 管理版本，当前为 **3**。启动时自动依次升级：版本 2 加入共享通知（保留原有任务通知及已读状态，共享通知从升级后的新发布开始生成），版本 3 支持一项任务有多位负责人。恢复旧版本的备份时，先在临时副本完成升级，成功后才替换当前数据库，原备份保持原版本。

任务每次更新在一个事务中写入当前状态及完整快照，停用成员的任务转交也在事务中完成。任务、共享条目使用版本号处理并发更新，冲突时返回 `409`，界面保留输入直到主动重新加载。
